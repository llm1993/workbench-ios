# 原生局域网文件传输

首版范围：Windows 工作台与原生 iOS 工作台之间双向直传。网页、Scriptable 和现有云端中转协议保持不变；不是将后端地址改成局域网 IP。双方都需要相同工作台服务器、账号与已解锁的内容密钥。

## 界面与使用

- 剪贴板底部的「文件传输」分为「附近与记录」和「云端中转」。
- Windows 文件页开启局域网接收，iOS 开启「查找附近设备」；首次使用需允许系统本地网络权限。Windows 防火墙由用户选择是否放行受信任的专用网络，不自动修改规则。
- 附近设备只有在通过当前账号内容密钥验证后才显示。点击连接后，首次仍需在电脑上明确批准配对。电脑名称只是显示信息，设备 ID、客户端签名公钥与证书指纹负责身份绑定。
- 选择文件后需确认目标；接收方允许后才传输。Windows 拖放不再等同于立即上传云端。
- 直传任务不创建后端中转文件，不占用云端配额。首版单文件上限 200 MiB，另外检查接收空间与本机队列容量。
- iPhone 的传输由 App 级管理器持有，离开文件页面不会丢失任务；进入后台暂停，回到前台可继续。它不是 iOS 后台传输服务。
- 批量选择先以受保护的文件书签保存到本机状态，所有可准备项形成加密队列后再逐个传输；暂停或上一项失败不会静默丢掉后续文件。文件提供者撤销访问、书签失效或源文件被移除时会显示错误，允许移除待处理项并重新选择。记录、待准备项、信任和忽略标记使用同一个原子状态文件。
- 已移除的接收记录有按设备/方向/fid 隔离的持久忽略标记，轮询不会立即把它重新加入；本机设置可显式清空忽略标记。保存信任最多 64 台，写入端也执行上限，不能让设备数异常连带擦掉历史。
- 收件续传按缺失密文块和一份明文组装空间检查磁盘，不会对已经缓存的部分重复预留；若上次在最终保存后中断，会校验并恢复成品，再补发回执。
- 接收到的文件保存到 App 受保护的本机文件区，完整校验和可靠保存后才回执。系统分享取消不会删除本机副本，可从记录中再次导出。
- 「已上传云端」「对方已接收」「已导出」是不同状态，不用 Bark 推送成功冒充文件已接收。
- 直传失败不会自动调用云端上传。只有明确确认「改用云端中转」后才复制加密队列并转入现有中转流程；云端中转可能仍需上传完整文件。自动开始意图只消费一次；手动暂停后，切换页面不会自动重新上传。
- 移除接收记录会删除该记录的本机接收副本，界面会再次确认；不影响对方文件或云端文件。

## 安全与协议

完整互操作协议见 [lan-transfer-v1.md](lan-transfer-v1.md)。

- Bonjour/mDNS 只负责发现，TXT 中的账号派生 HMAC 绑定设备、证书指纹、端口和显示名称。局域网请求与主账号请求使用完全分离的客户端。
- 独立 HKDF 认证键、HTTPS 证书精确固定、Ed25519 请求签名、时间窗与 nonce 防重放；不发送账号 Bearer Token，不跟随重定向，不信任任意自签名证书。
- iOS 签名身份使用独立 Keychain 项，并按账号/服务器/内容密钥 ID 隔离。账号切换、退出和加密密钥变更会取消旧任务；改口令但不换内容密钥不改变文件加密格式。
- 原有 `clipstudio:file:v1` AAD、4 MiB 分块、nonce/ciphertext/tag、元数据加密与固定向量全部保留。
- 本机待发送与未完成接收块使用加密文件；接收成品采用 iOS 完全文件保护，并排除备份。分享不会改变原加密协议，也不会自动打开文件。
- 本地发现、信任和接收权限独立于云端在线状态；仅撤销云端登录不等于远程即时撤销离线设备已经持有的密钥。丢失设备应同时撤销设备信任，必要时按既有流程重设内容密钥。

## 检查

Windows 源码在兄弟 `workbench/windows/clipstudio-rs`。共享协议向量是该仓库 `tests/vectors/lan-transfer-v1.json` 的逐字节副本；由独立 Python cryptography 生成，不调用任何客户端实现。

本机可执行：

```bash
python scripts/check-lan-transfer.py
```

```bash
python scripts/check-native.py --syntax-libs ../scratch/native-check-libs
```

Xcode 原生测试需要 macOS：`LANTransferTests` 覆盖 scope/HKDF、发现认证、Ed25519 请求、路径边界、续传块号、文件元数据、空文件、校验失败、持久接收、安全文件名、批量意图恢复、忽略标记、初始化重试、信任容量、对端公告上限和续传空间；UI 用例包含新入口、明确云端切换与辅助字号。Windows 使用真实 TLS loopback 集成测试。

语法、静态检查和 Windows loopback 不能证明实际 iPhone 本地网络授权、Bonjour 跨设备发现、Windows 防火墙、iOS 后台恢复及真实 Wi-Fi 吞吐。未明确请求构建时不触发手动 IPA workflow，也不复用旧 IPA 的验证结论。
